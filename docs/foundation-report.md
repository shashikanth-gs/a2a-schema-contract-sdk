## Reproduction and results

From `js/`, using patched Node 22 or 24:

```sh
npm ci
npm run check
npm run check:clean
npm audit
```

`check:clean` copies only this repository's JS sources, reviewed vendor snapshot,
pin and license into a new temporary directory, then runs **npm ci + npm run
check**. It excludes existing modules/builds/reports and has no `inputs/`
directory. Consumer tests subsequently install a tarball in another independent
temporary directory. Both directories are removed in `finally` blocks.

## Reports and artifact identity

Reports under `js/reports/`:

- `clean-node22.json` / `clean-node24.json`: supported environment, command results
  and full coverage totals; corresponding `.log` files retain aggregate output.
- `package-node22.json` / `package-node24.json`: artifact version/SHA-256/SHA-512,
  installed files, upstream revision, ten consumer gates, exact peer bounds and
  consumer lock hash.
- `dependency-audit.json`, `dependency-tree.json`, `licenses.json`: fresh reviewed
  resolution, security result and SPDX inventory (including platform dev packages).

Both supported runtime builds produced the same
`shashikanth-gs-a2a-schema-contract-0.1.0-dev.0.tgz` SHA-256:
`e8d328aa34b3ad555648f7933b060403650c3a8118e42af946506cdbd6144668`.

`npm run test:package`. Their documented public imports work without SDK source,
workspace inputs, Express/providers/development tools, or a build-time download.

peer; core declaration checking does not.
